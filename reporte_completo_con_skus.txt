--------------------------------------------------------------------------------
2. REPARACIÓN DEL INVENTARIO
--------------------------------------------------------------------------------
1. Se ejecutó un script corrector local agrupando los 154 SKUs en 31 lotes,
   el cual sobrescribió los balances de inventario y los cuadró exactamente
   con Zoho.
2. Se arregló un formato de ID incorrecto y se realizó una sincronización
   global forzosa, lo cual permitió importar los 2 artículos huérfanos.


--------------------------------------------------------------------------------
3. SEGUIMIENTO A LA CAUSA RAÍZ (LA COLA ATASCADA)
--------------------------------------------------------------------------------
Se detectó que el problema de que el ERP no procesara los webhooks de Zoho
se debía a un embudo en la base de datos (tabla sync_queue):
- 4,340 tareas pendientes.
- 1,315 tareas fallidas (Unknown silent failure).

> Bug Lógico Descubierto:
Si un producto se quedaba sin existencias (0 stock), el código lo consideraba
un error de red/silencioso. El sistema no lo actualizaba a 0, sino que
lo devolvía a la cola para reintentarlo infinitamente, saturando y bloqueando 
las demás actualizaciones de stock regulares.


--------------------------------------------------------------------------------
4. SOLUCIÓN DEFINITIVA Y PREVENCIÓN
--------------------------------------------------------------------------------
A. CORRECCIÓN DE CÓDIGO
   Se eliminó la restricción de stock cero en route.ts. Ahora los productos
   que bajan a 0 se procesan limpiamente, se actualizan y se remueven
   de la cola con normalidad.

B. LIMPIEZA DE BASE DE DATOS
   Se vaciaron las 5,600 tareas atrasadas de la tabla sync_queue mediante
   SQL. Puesto que ya se sincronizó todo el catálogo en el paso 2, el backlog
   ya era irrelevante. La cola arrancó desde 0, completamente limpia.

C. INSTRUCCIÓN FINAL DE AUTOMATIZACIÓN
   Para blindar el sistema, se verificó que el cron job externo (cron-job.org)
   debe estar configurado obligatoriamente:
   - Apuntando a /api/cron/process-queue?cron_secret=solcom-cron-key-123
   - Corriendo con una periodicidad de 1 minuto.
   - Usando el método GET.
